# Operational Runbook for ETL Pipeline

## Deployment

1. **Prerequisites**
   - Ensure Python 3.10+ is installed.
   - Install required packages using the command:
     ```
     pip install -r requirements.txt
     ```
   - Set up the PostgreSQL database and ensure the `manual.crypto_market_snapshot` and `manual.pipeline_runs` tables are created.

2. **Environment Variables**
   - Create a `.env` file in the project root with the following variables:
     ```
     DB_HOST=<your_db_host>
     DB_PORT=<your_db_port>
     DB_NAME=<your_db_name>
     DB_USER=<your_db_user>
     DB_PASSWORD=<your_db_password>
     ETL_ENV=<development/production>
     GITHUB_TOKEN=<your_github_token>
     GITHUB_OWNER=<your_github_owner>
     GITHUB_REPO=<your_github_repo>
     API_KEY=<your_api_key>
     ```

3. **Running the ETL Pipeline**
   - Execute the ETL script using:
     ```
     python crypto_etl.py
     ```

## Monitoring

1. **Log Files**
   - Monitor the log files generated by the ETL process for any errors or warnings.
   - Logs are stored in the `logs/` directory and can be accessed for troubleshooting.

2. **Database Monitoring**
   - Use PostgreSQL monitoring tools to check the performance of the `crypto_market_snapshot` and `pipeline_runs` tables.
   - Ensure that the number of rows in `pipeline_runs` reflects the expected number of processed records.

## Alerting

1. **Error Notifications**
   - Set up alerts to notify the development team via email or messaging service (e.g., Slack) if the ETL process fails.
   - Use monitoring tools like Prometheus or Grafana to visualize ETL performance metrics.

2. **Threshold Alerts**
   - Configure alerts for when the number of rows loaded into `crypto_market_snapshot` falls below 40, indicating potential issues with data extraction.

## Rollback

1. **Rollback Strategy**
   - In case of a failure during the ETL process, the transaction will automatically roll back due to the atomic nature of the TRUNCATE+INSERT pattern.
   - If the ETL process fails, review the logs to identify the cause and fix the issue before re-running the pipeline.

2. **Manual Rollback**
   - If necessary, manually revert to the last known good state by restoring the `crypto_market_snapshot` table from a backup.
   - Ensure that backups are taken regularly to facilitate quick recovery.

3. **Testing Rollback Procedures**
   - Regularly test the rollback procedures to ensure they work as expected and that the team is familiar with the process.
